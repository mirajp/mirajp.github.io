# Decision 0.4c: CSP delivery for the static Astro host

## Decision

Apply a page-local CSP meta policy to `/tools/svg-editor/` during the production
build. GitHub Pages cannot set response headers, and a site-wide policy would
change unrelated pages. The post-build script hashes each emitted inline script
and allows only those hashes plus same-origin scripts. It fails if the built
editor page or its `<head>` is missing.

The policy uses `default-src 'none'`, same-origin scripts, no connections,
objects, frames, or external bases, and permits only same-origin plus data/blob
images and same-origin/data fonts. `style-src 'unsafe-inline'` is necessary for
the editor's SVG style attributes, retained `<style>` content, and imperative
pane transforms. This weakens CSS injection protection, so the sanitizer strips
external CSS URLs/imports and `img-src`/`connect-src` prevent network exfiltration.
`frame-ancestors` cannot be enforced from a meta policy; GitHub Pages offers no
header configuration, so clickjacking policy remains a hosting limitation.

## Build integration and verification

`yarn build` (or `pnpm build`) runs Astro and then
`scripts/svg-editor/csp/postprocess.mjs`. The script updates only
`dist/tools/svg-editor/index.html`; it does not alter other page HTML or JS.
E2E runs against the built output and checks editor functionality under this
policy.
